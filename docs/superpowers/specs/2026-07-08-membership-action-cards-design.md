# MembershipActionSheet 卡片化改造 设计文档

> 日期: 2026-07-08 | 状态: 已确认

## 一、背景

当前 MembershipActionSheet 的会员等级选择使用原生 `<select>` 下拉，用户无法在选择前看到各等级的完整信息（月费、店铺数、每日风铃石），形成"盲盒"体验。风铃石充值同样是下拉，缺乏信息展示。

改造目标：将选择交互从 `<select>` 改为信息卡片，用户可看到完整信息后再做选择。

## 二、改动范围

仅修改 1 个文件：`app/admin/users/MembershipActionSheet.tsx`

不新增文件，不修改 API 层。

## 三、通用卡片组件：PlanCard / StoneCard

PlanCard 和 StoneCard 是 MembershipActionSheet 内部定义的私有组件（不对外导出，仅本文件使用）。

### 3.1 PlanCard（会员等级卡片）

**Props**：
```ts
interface PlanCardProps {
  plan: MembershipPlan            // 等级数据（含 tier/max_accounts/price/daily_bonus）
  selected: boolean               // 是否选中
  onClick: () => void             // 点击回调
  disabled?: boolean              // 是否禁用（如当前等级卡片不可选）
}
```

**展示信息**：
- 第一行：左侧等级 Badge（Free/Basic/Standard/Pro）+ 等级中文名，右侧 `fmtPrice(price)` /月
- 第二行：灰色小字 "最多 N 个店铺" + "每日 +N 风铃石"

**状态样式**：

| 状态 | border | background | cursor |
|------|--------|------------|--------|
| 默认 | `border-gray-200` | `bg-white` | `pointer` |
| hover | `border-blue-300` | `bg-gray-50` | `pointer` |
| 选中 | `border-blue-500 ring-1 ring-blue-500` | `bg-blue-50` | `default` |
| disabled | `border-gray-100` | `bg-gray-50` | `default`（不可点击，续费场景当前等级卡片） |

**卡片结构**：
```
┌──────────────────────────────────────────────────┐
│  [Pro badge]     Pro                ¥299/月       │  ← text-sm font-semibold 等级名
│  最多 20 个店铺    每日 +50 风铃石                │  ← text-xs text-gray-500
└──────────────────────────────────────────────────┘
```

卡片内边距 `p-3`，纵向 `space-y-1`，圆角 `rounded-lg`，过渡 `transition-colors`。

### 3.2 StoneCard（风铃石充值档位卡片）

**Props**：
```ts
interface StoneCardProps {
  pricing: StoneSalePricing       // 定价数据（amount=售价分, stones=风铃石数）
  selected: boolean
  onClick: () => void
}
```

**展示信息**：
- 第一行：价格大字 `fmtPrice(amount)`，`text-base font-semibold`
- 第二行：灰色小字 `"N 风铃石"`

**状态样式**：与 PlanCard 相同规则（默认/悬浮/选中三态）。

**卡片结构**（更紧凑）：
```
┌────────────────────┐
│      ¥6            │  ← text-base font-semibold
│    60 风铃石        │  ← text-xs text-gray-500
└────────────────────┘
```

横向排列，`grid grid-cols-2` 或 `grid-cols-3`，`gap-2`。卡片 `p-3 rounded-lg`。

## 五、价格自动计算逻辑

### 5.1 升级金额

```ts
function calcUpgradeAmount(currentPlan: MembershipPlan, targetPlan: MembershipPlan): number {
  const priceDiff = targetPlan.price - currentPlan.price   // 差价
  const now = new Date()
  const endOfMonth = new Date(now.getFullYear(), now.getMonth() + 1, 0)
  const daysInMonth = endOfMonth.getDate()
  const remainingDays = Math.max(
    Math.ceil((endOfMonth.getTime() - now.getTime()) / (1000 * 60 * 60 * 24)),
    1  // 最少 1 天
  )
  return Math.round(priceDiff * remainingDays / daysInMonth)
}
```

展示文本：`¥{priceDiff} × {remainingDays}天 ÷ {daysInMonth}天 ≈ ¥{result}`

### 5.2 续费金额

```ts
// 月数 × 单价（实时计算，不需要单独函数）
const calcRenewAmount = durationMonths * currentPlan.price
```

展示文本：`{durationMonths} × ¥{currentPlan.price}/月 = ¥{result}`

### 5.3 降级金额

不自动计算，默认 `0`，选填。

### 5.4 触发时机

- 升级/降级：点击选中一张等级卡片时，自动计算并填入金额字段
- 续费：月数 `onChange` 时实时更新金额
- 用户始终可以在自动计算后手动修改金额

## 六、状态管理变更

现有状态无需大改，仅调整一处：

- 移除 `stoneAmount` 状态（充值改用 `targetTier` 选中的定价 ID）
- 实际上，充值使用 `selectedStoneAmount` 来跟踪选中的 `amount` 值
- 保留 `targetTier`（升级/降级）、`amountCents`、`durationMonths`、`remark`、`submitting`

实际上当前状态已经够用，不需要改状态变量名，只需调整赋值逻辑：

- `stoneAmount` 继续作为充值选中档位的 `amount` 值（查询参数用）
- 升级/降级中 `targetTier` 在点击卡片时设置

## 七、卡片列表的边界处理

| 场景 | 处理 |
|------|------|
| 升级时无更高等级 | 列表区显示 EmptyState："已是最高等级" |
| 降级时无更低等级 | 列表区显示 EmptyState："已是最低等级" |
| 加载 plans 失败 | 列表区显示 ErrorBanner + 重试按钮 |
| 风铃石定价列表为空 | 列表区显示 EmptyState："暂无可选定价" |
| plans 返回空数组 | 同"加载失败"，显示 ErrorBanner |

## 八、设计决策

| 决策 | 选择 | 原因 |
|------|------|------|
| 卡片 vs select | 卡片 | 信息透明，用户可在选择前了解完整等级信息 |
| PlanCard 不对外导出 | 私有组件 | 仅此文件使用，符合就近原则 |
| 升级金额自动计算 | 差价 × 剩余天数 / 月天数 | 按比例计算补差价，符合业务逻辑 |
| 续费金额实时刷新 | 月数 onChange 触发 | 用户调月数时即时看到总价变化 |
| 降级不自动计算 | 默认 0 | 降级通常免费，不强制计算 |
| 金额字段仍可手动修改 | input 可编辑 | 管理员可能需要调整具体金额 |

## 九、不涉及的范围

- API 层或数据模型变更
- 新增独立文件或组件
- 其他页面的改动
